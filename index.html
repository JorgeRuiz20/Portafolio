MotoStock — Android

Un taller de motos necesita controlar repuestos, servicios, vehículos y citas sin depender de procesos dispersos. La propuesta fue llevar esa operación a una aplicación Android centralizada, con información persistente, acceso por roles y capacidad de seguir trabajando con datos locales.

Qué construí

Una app nativa para gestionar inventario, historial de servicios por placa y agenda de citas, con autenticación y sincronización en la nube.

Cómo lo resolví

Separación por capas y responsabilidades con Clean Architecture, ViewModels/StateFlow, Room para persistencia local, Firestore para sincronización, Retrofit para integración externa y Hilt para inyección de dependencias.

KotlinJetpack ComposeClean ArchitectureMVVM / StateFlowHiltRoomRetrofitFirebase
  • Roles CLIENTE / TRABAJADOR / ADMIN
  • Firebase Auth + Google Sign-In
  • FCM para notificaciones
  • Room + Firestore para persistencia y sincronización
  • Consulta de datos de vehículo vía API
  • Tests con JUnit + Mockito y patrón AAA

Carwash H&R — Gestión operativa

La operación de un lavadero concentra clientes, vehículos, servicios, caja e inventario. A partir de esa problemática construí una solución dividida entre un backend REST y una interfaz web para digitalizar el flujo y centralizar la información del negocio.

Qué construí

Una API para la lógica de negocio y una SPA para consultar y operar los procesos desde una interfaz web.

Cómo lo resolví

Spring Boot + MySQL para el backend, Docker para empaquetado y despliegue, y React + Vite + Axios para consumir la API desde el frontend.

JavaSpring BootREST APIMySQLDockerReactViteAxios
  • Gestión de servicios, clientes y empleados
  • Caja diaria, pagos y arqueo
  • Inventario y control de insumos
  • Reportes y seguimiento operativo
  • Frontend responsive conectado a la API
  • Despliegue containerizado en la nube

Robotech — Gestión comercial

La propuesta busca ordenar la gestión de una empresa de robótica donde inventario, clientes, ventas, cotizaciones y pedidos necesitan estar conectados. El proyecto separa la lógica de negocio de la interfaz para construir una solución más mantenible y fácil de evolucionar.

Qué construí

Un backend REST para gestionar inventario, ventas, cotizaciones y clientes, acompañado de una interfaz web para operar el sistema.

Cómo lo resolví

Spring Boot + JPA/Hibernate + MySQL para persistencia y reglas del sistema. El frontend usa React + Vite, React Router, Axios y componentes de interacción para consumir la API.

JavaSpring BootJPA / HibernateMySQLJUnitReactViteAxiosReact Router

RinRed — Reservas de taxi en Cusco

La idea fue crear una experiencia sencilla para solicitar un taxi, consultar viajes en curso o finalizados y gestionar cancelaciones, enfocada en un servicio de transporte dentro de Cusco. El proyecto permitió practicar el flujo completo entre una interfaz web y una API propia.

Qué construí

Un frontend multipágina con Bootstrap para explorar el servicio, solicitar taxis, consultar viajes y revisar información del conductor.

Cómo lo resolví

Backend con Spring Boot 3.5.3, Java 21, Spring Data JPA y MySQL; frontend con HTML, CSS, JavaScript y Bootstrap, consumiendo la API y manteniendo datos de sesión con localStorage.

Java 21Spring BootSpring Data JPAMySQLDockerHTMLCSSJavaScriptBootstrap
  • Solicitud de taxi
  • Consulta de viajes pendientes y finalizados
  • Cancelación de viajes
  • Consulta de información del conductor
  • Integración frontend ↔ API REST
  • Interfaz responsive para navegación web
